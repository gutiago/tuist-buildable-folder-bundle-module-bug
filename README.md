# Tuist buildable folders: flat root-level file references (two related issues)

Minimal reproducible project for **Tuist 4.198.1** demonstrating two `buildableFolders:` gaps that each materialise stray, duplicated flat `PBXFileReference` entries at the generated project root.

## Repro

```sh
mise install
tuist generate --no-open
```

Then open `App.xcodeproj/project.pbxproj` (or the project in Xcode) and look at the root `Project` group.

## Issue A — xcconfigs / Info.plist inside a buildable folder get flat root-level references

The `App` target uses `buildableFolders: ["App"]`. Its `infoPlist: .file(path:)` and both configuration xcconfigs live **inside** that folder:

```swift
infoPlist: .file(path: "App/Supporting/App-Info.plist"),
buildableFolders: [
  .folder("App", exceptions: [.exception(excluded: ["Supporting/App-Info.plist"])]),
],
settings: .settings(configurations: [
  .debug(name: "Debug", xcconfig: "App/Supporting/Configurations/App-Debug.xcconfig"),
  .release(name: "Release", xcconfig: "App/Supporting/Configurations/App-Release.xcconfig"),
])
```

### Expected

Xcode 16+ handles this layout with an *anchored* reference on `XCBuildConfiguration` — no standalone file reference. From a hand-maintained `objectVersion = 71` project with the same shape:

```
isa = XCBuildConfiguration;
baseConfigurationReferenceAnchor = 43D0E0BD2FADF11200C6BFC5 /* iAuditor */;
baseConfigurationReferenceRelativePath = "Supporting/Configurations/iAuditor.notificationserviceextension/iAuditor.notificationserviceextension-Debug.xcconfig";
```

(`43D0E0BD…` is the `PBXFileSystemSynchronizedRootGroup` of the folder.) XcodeProj doesn't model `baseConfigurationReferenceAnchor` / `baseConfigurationReferenceRelativePath` yet, so Tuist falls back to a plain `baseConfigurationReference` plus a flat file reference.

### Actual (generated by this project)

Flat root-level `PBXFileReference`s, duplicating files already visible inside the synchronized `App` folder:

```
EFCAC8CCD082C2E81A36842D /* App-Debug.xcconfig */ = {isa = PBXFileReference; lastKnownFileType = text.xcconfig; name = "App-Debug.xcconfig"; path = "App/Supporting/Configurations/App-Debug.xcconfig"; sourceTree = "<group>"; };
060D8C8C508C75B9FA615E8D /* App-Info.plist */ = {isa = PBXFileReference; lastKnownFileType = text.plist; name = "App-Info.plist"; path = "App/Supporting/App-Info.plist"; sourceTree = "<group>"; };
37DA2AE0F12AA7A88096B626 /* App-Release.xcconfig */ = {isa = PBXFileReference; lastKnownFileType = text.xcconfig; name = "App-Release.xcconfig"; path = "App/Supporting/Configurations/App-Release.xcconfig"; sourceTree = "<group>"; };
```

referenced from the build configurations as:

```
baseConfigurationReference = EFCAC8CCD082C2E81A36842D /* App-Debug.xcconfig */;
...
baseConfigurationReference = 37DA2AE0F12AA7A88096B626 /* App-Release.xcconfig */;
```

and parked in the root `Project` group, next to the synchronized folder that already contains them:

```
52611B11A5E6A7198C4E57A3 /* Project */ = {
  isa = PBXGroup;
  children = (
    B3BCDE38B26B330C9A04FADE /* Derived */,
    F3A3AFE8AE45ED0688E0E335 /* App */,                      // synchronized folder containing the same files
    EFCAC8CCD082C2E81A36842D /* App-Debug.xcconfig */,        // duplicate flat ref
    060D8C8C508C75B9FA615E8D /* App-Info.plist */,            // duplicate flat ref
    37DA2AE0F12AA7A88096B626 /* App-Release.xcconfig */,      // duplicate flat ref
    211706413340F37A18D8D494 /* AppTests */,
    CBCA14B984639D167AA87655 /* SharedStub.swift */,          // Issue B, see below
  );
  name = Project;
  ...
```

Note `.exception(excluded:)` does not help — exceptions control build membership, not navigator display. Everything builds; the issue is navigator clutter/duplication, which scales badly for xcconfig-driven projects (one xcconfig per target per configuration).

## Issue B — no API for additive cross-target buildable-folder membership

`App/SharedStub.swift` lives inside the `App` target's buildable folder but must also compile into `AppTests` (the test in `AppTests/AppTests.swift` references it). The only manifest API available is an explicit glob on the consuming target:

```swift
.target(
  name: "AppTests",
  ...
  sources: [.glob("App/SharedStub.swift")],   // lives in another target's buildable folder
  buildableFolders: ["AppTests"])
```

### Expected

Xcode 16 models cross-target membership natively with a `PBXFileSystemSynchronizedBuildFileExceptionSet` on the owning folder whose `target` points at the *foreign* target — for the owning target the listed paths are exclusions, for a foreign target they are inclusions. No standalone `PBXFileReference`/`PBXBuildFile`; the navigator shows the file once. From a hand-maintained `objectVersion = 71` project:

```
43D04FAE2FADF4B700C6BFC5 /* PBXFileSystemSynchronizedBuildFileExceptionSet */ = {
    isa = PBXFileSystemSynchronizedBuildFileExceptionSet;
    membershipExceptions = (
        "Home/Stubs/ProfileOptionsSyncStatusViewModelStub.swift",
        ...
    );
    target = <iAuditorSnapshotTests>;   // NOT the folder's owning target
};
```

Tuist's `BuildableFolderException` only supports `.exception(excluded:)` — the subtractive half for the owning target. There is no way to express "also compile this file into target B", e.g.:

```swift
.exception(target: "AppTests", included: ["SharedStub.swift"])   // does not exist
```

### Actual (generated by this project)

The `sources:` glob builds correctly but materialises another flat root-level `PBXFileReference` + `PBXBuildFile`, duplicating the file shown inside the `App` synchronized folder:

```
05F1878EE824C1C0467D3E47 /* SharedStub.swift in Sources */ = {isa = PBXBuildFile; fileRef = CBCA14B984639D167AA87655 /* SharedStub.swift */; };
...
CBCA14B984639D167AA87655 /* SharedStub.swift */ = {isa = PBXFileReference; lastKnownFileType = sourcecode.swift; name = SharedStub.swift; path = App/SharedStub.swift; sourceTree = "<group>"; };
```

The only exception set Tuist generates is the subtractive one for the owning target (the Info.plist exclusion from Issue A):

```
7ED3886B5850FC5C48F80D80 /* PBXFileSystemSynchronizedBuildFileExceptionSet */ = {
    isa = PBXFileSystemSynchronizedBuildFileExceptionSet;
    ...
    membershipExceptions = (
        "Supporting/App-Info.plist",
    );
    target = 93E9E330FC2CE7458D9C925F /* App */;   // owning target only — no foreign-target form
};
```

XcodeProj already round-trips `PBXFileSystemSynchronizedBuildFileExceptionSet` with its `target` attribute (Tuist uses it today for exclusions), so this appears to be a ProjectDescription/generator API gap rather than a format-layer one.

## How the issues compound

Anchored `baseConfigurationReference` support (Issue A) would fix where config/plist references point; additive exception sets (Issue B) remove the need for flat references for cross-target sources/resources. In a real migration (~65 manifests, xcconfig-authoritative settings, 5 configurations, plus 13 cross-target files) the generated project root accumulates 35+ stray xcconfig/Info.plist refs and 13 stray source/resource refs.

## Environment

- Tuist 4.198.1 (mise)
- Xcode 26.4.1
- macOS 15
